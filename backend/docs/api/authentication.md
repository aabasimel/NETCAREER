## Authentication API

This document describes how authentication works in the NETCAREER backend and how to use the available endpoints.

### Overview

- Auth method: JWT (SimpleJWT) with access and refresh tokens
- Token lifetimes: access = 1 day, refresh = 1 day
- Email verification is required before login
- Default auth classes: JWT, Session, Token, and Basic (see `config/settings.py`)

### Base URL

Assume all endpoints are under your backend API base. Examples below use relative paths:

- Register: `POST /auth/register/`
- Verify email: `GET /auth/verify-email/?token=...`
- Login: `POST /auth/login/`
- Logout (invalidate all tokens for current user): `POST /auth/logout/`
- Current user profile: `GET/PATCH /profile/`

## Endpoints

### Register

POST `/auth/register/`

Creates a new user and sends a verification email. If the email already exists but the account is not verified, a verification email may be re-sent.

Request body (JSON):

```
{
	"email": "user@example.com",
	"password": "StrongPassw0rd!",
	"password_confirm": "StrongPassw0rd!",
	"first_name": "Jane",
	"last_name": "Doe",
	"role": "jobseeker"  // or "employer"
}
```

Responses:

- 201 Created: registration success and verification email sent
- 200 OK: verification email re-sent to existing unverified user
- 400 Bad Request: email already verified or validation error

Notes:

- The verification link includes a short-lived JWT generated by the server.
- The token encodes `user_id`, `email`, and a `type` of `email_confirmation`.

### Verify Email

GET `/auth/verify-email/?token=<jwt>`

Marks the user’s account as verified and active when a valid token is provided.

Query params:

- `token`: URL-encoded JWT emailed to the user

Responses:

- 200 OK: email verified (or already verified)
- 400 Bad Request: invalid or expired token
- 404 Not Found: user not found

### Login

POST `/auth/login/`

Authenticates with email and password and returns JWT access and refresh tokens. The user must be verified before login.

Request body (JSON):

```
{
	"email": "user@example.com",
	"password": "StrongPassw0rd!"
}
```

Response (200 OK):

```
{
	"access": "<jwt-access-token>",
	"refresh": "<jwt-refresh-token>"
}
```

Errors:

- 401 Unauthorized: invalid credentials
- 403 Forbidden: email not verified
- 429 Too Many Requests: rate limit exceeded (login is limited to 5 requests/min per client)

### Logout (invalidate all tokens)

POST `/auth/logout/`

Invalidates all outstanding tokens for the authenticated user. Requires `Authorization: Bearer <access>`.

Headers:

- `Authorization: Bearer <access-token>`

Responses:

- 200 OK: all tokens invalidated for the user (logged out from all devices)
- 400 Bad Request: error during invalidation

Note:

- There is also a utility function internally (`logout_view`) that blacklists a specific refresh token, but it is not exposed via URLs. The primary supported flow is logging out the current user and invalidating all outstanding tokens.

### Current User Profile

GET `/profile/`

Returns the authenticated user’s profile.

PATCH `/profile/`

Updates the authenticated user’s profile.

Headers:

- `Authorization: Bearer <access-token>`

## Curl Examples

Replace the base URL and tokens as needed.

### Register

```bash
curl -X POST \
	https://api.example.com/auth/register/ \
	-H 'Content-Type: application/json' \
	-d '{
		"email": "user@example.com",
		"password": "StrongPassw0rd!",
		"password_confirm": "StrongPassw0rd!",
		"first_name": "Jane",
		"last_name": "Doe",
		"role": "jobseeker"
	}'
```

### Verify Email

```bash
curl "https://api.example.com/auth/verify-email/?token=<url-encoded-jwt-token>"
```

### Login

```bash
curl -X POST \
	https://api.example.com/auth/login/ \
	-H 'Content-Type: application/json' \
	-d '{
		"email": "user@example.com",
		"password": "StrongPassw0rd!"
	}'
```

Example success:

```
{
	"access": "eyJ0eXAiOiJKV1QiLCJhbGci...",
	"refresh": "eyJ0eXAiOiJKV1QiLCJhbGci..."
}
```

### Logout (invalidate all tokens)

```bash
curl -X POST \
	https://api.example.com/auth/logout/ \
	-H 'Authorization: Bearer <access-token>'
```

### Get current profile

```bash
curl https://api.example.com/profile/ \
	-H 'Authorization: Bearer <access-token>'
```

### Update current profile

```bash
curl -X PATCH \
	https://api.example.com/profile/ \
	-H 'Authorization: Bearer <access-token>' \
	-H 'Content-Type: application/json' \
	-d '{
		"first_name": "Janet",
		"last_name": "Doe"
	}'
```

## Implementation Notes

- SimpleJWT configuration is in `config/settings.py` via `SIMPLE_JWT` with user ID claim `user_id`.
- Email verification tokens are generated and validated using HS256 with `settings.SECRET_KEY`.
- Login requires the user to be verified (`is_verified = True`).
- Logout via `/auth/logout/` will invalidate all outstanding tokens for the current user.

## Common Errors

- 400: validation error (e.g., password policy, email already verified)
- 401: invalid credentials
- 403: email not verified
- 404: user not found (verification step)

## Security Tips

- Always send the `Authorization: Bearer <access-token>` header for protected endpoints.
- Store refresh tokens securely; treat them as secrets.
- Use HTTPS in production.
